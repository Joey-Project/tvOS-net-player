# Native Task Watch Recovery UI E2E

## Scope
- Continue the approved [native recovery UI coverage](2026-10-19-macos-computer-use-e2e-b46384.md) after [PR #80](https://github.com/Joey-Project/tvOS-net-player/pull/80).
- PR #80 merged as `5c484955fc69fa86e77cc2d0abd958268aafcce3`; its tree matches the exact reviewed head `5a74018c0c3c5cf14fc67048f2ebd2c227a97dd9`. Local master was fast-forwarded before creating this branch.
- Exercise the shared recovery behavior through actual macOS/tvOS controls and the production gRPC client. Existing model and wire tests are not native UI acceptance.
- Keep the ordinary local-media playback E2E against the real Rust server. Add deterministic control-plane failures without changing household services, production routing, credentials or public-proxy configuration.

## Acceptance Plan
- Use an isolated loopback-only control/media fixture with bounded lifetime, explicit fault injection and an inspectable task-creation count. Prefer existing fixture infrastructure; do not add a production secret-writing or test-control backdoor.
- Submit and select through visible controls. Inject a transient observation failure, show reconnecting state, reconcile the same task, and prove eventual recovered state with exactly one task creation.
- Exhaust the bounded observation retry budget, exercise the visible Reconnect Updates control, and prove that retry reads the accepted task before subscribing without submitting again.
- Cover safe cancellation/terminal presentation proportionately, retaining model and real-wire regressions for race interleavings. Do not substitute hidden view-model calls for a UI action.
- Preserve playable media during a control-plane outage. Test the native view and task identity; keep media decoding evidence distinct from task-state assertions.
- Both platforms must execute their intended recovery cases with nonzero verified counts and zero failures or skips. Existing media E2E must remain required.

## Fixture Contract
- Keep the existing Rust media server and original playback case. A separate `task-watch-ui-fixture` Swift executable serves only deterministic control-plane replies on an ephemeral IPv4 loopback listener, using the canonical Protobuf schema and pinned dependencies.
- Pass its separate endpoint through `UI_E2E_TASK_SERVER_ADDRESS` in both UI TestActions. The original `UI_E2E_SERVER_ADDRESS` continues to identify the real Rust server.
- Recognize only the two canonical fixture inputs: `BV1QtjA6BEB8` for automatic recovery and `BV1uW4y1s7zN` for manual recovery. These identifiers do not authorize or initiate an internet fetch.
- Keep task identity and playable output stable across injected typed transport failures. Manual recovery uses the production six-delay budget, totaling 47 seconds; do not shorten model timers for UI tests.
- Persist bounded, credential-free per-scenario counters and task IDs. The runner must independently reject duplicate task creation and require evidence that the manual resume read preceded the final subscription.
- Require the existing platform playback method plus `testAutomaticTaskWatchRecoversWithoutResubmission` and `testManualTaskWatchReconnectPreservesPlayback` in actual result metadata. A positive aggregate count alone is insufficient.
- A transient watch warning is not proof that observation stopped. The manual case waits for the warning and retry control to exist while the reconnecting indicator is absent before exercising playback and reconnection.

## Boundaries
- No live Bilibili, credential, audible-audio, physical-device, deployment or release acceptance is implied by deterministic fixtures.
- Silent-stream heartbeat detection, protocol/schema expansion and upstream enumeration remain outside this focused UI-test slice.

## Implementation Decisions
- Reuse the canonical generated Protobuf types with Swift `package` visibility. The fixture does not expose generated messages as a new public client API or maintain a second schema copy.
- Restrict fixture media to credential-free loopback HTTP URLs. Accept the real Rust server's `/media/local.default.<base64url>/original` route, not only file-extension URLs; verify its content type and exact fixture length before launching the test service.
- Preserve the production retry delays in native tests. Only the in-process AppCore/gRPC regressions inject a short recovery sleeper; they exercise the same V2 resolution, task creation, result mapping and observation code without decoding media.
- Play the explicitly identified V2 result through its existing row action, rather than the separate legacy task-level Play control. On tvOS the result action is above Submit in the left scroll area; remote navigation follows that actual layout.
- Independently validate fixture metrics after native test completion: stable expected task IDs, exactly one creation per scenario, no task cancellation, real watch/read/output calls and an observed manual `GetTask` before the new subscription.
- Require every named native case from xcresult metadata. Keep bounded fixture readiness, metrics and process logs with the existing allowlisted diagnostics; clean up only the test-owned servers and simulator.
