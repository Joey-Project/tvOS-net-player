# Deterministic Native UI E2E And Runner Validation

## Approved Scope
- Follow the macOS repair merged in [PR #78](https://github.com/Joey-Project/tvOS-net-player/pull/78), starting from master `203a904b8e318559126bddcfb513555f8bcbd142`.
- Add explicit macOS and tvOS XCUITest targets. Exercise visible app workflows rather than calling view-model methods or relabeling hosted-view/unit tests as UI e2e.
- Validate actual execution on GitHub-hosted macOS runners, including the tvOS simulator. Compilation, runtime inventory and successful existing unit tests alone are not execution proof.

## Design
- Use the real Rust LAN cache server on loopback with isolated state, a generated silent H.264 MP4 and 55 distinct cache entries to cross the library's 50-item boundary. Keep gRPC control and HTTP Range media paths intact.
- Launch debug test apps with isolated preferences and discovery disabled. The test must enter the fixture server address through visible controls; it must not remember or auto-connect to a household server.
- Keep the fixture server's Bilibili worker, login sessions and Bonjour disabled. Do not read saved credentials, issue login requests, access Bilibili or require public reverse proxies in ordinary CI.
- Cover launch, server connection, library selection/paging and native playback progression; cover playback pause/resume, skip and speed through visible controls where available. Use tvOS remote focus/selection for tvOS interaction.
- Bound fixture generation, startup/readiness, builds/tests and retained diagnostics. Stop and reap only owned processes; never reset production services or delete unowned caches. Retain bounded failure summaries/activity metadata and eligible xcresult bundles; screenshot and accessibility payloads remain available only when their bundle fits the archive limits.
- Set and verify system audio mute before playback, keep it muted afterward and generate media without an audio track. Muted tests do not validate audible output.

## Delivery Sequence
1. Implement disjoint app/test, Xcode wiring and fixture/runner/CI slices using GPT-6 Luna workers; integrate with GPT-6.1 Sol coordination.
2. Run focused helper/format/lint checks and real local UI execution, then the complete relevant suite. Preserve the distinction between an environment block, failed test and executed pass.
3. Freeze a signed head, open a focused PR, use only GitHub `@codex review`, and require complete current-head CI and resolved conversations before merge. Workflow ownership approval remains a separate gate; do not impersonate a human approval or bypass rules.

## Boundaries
- The prior fresh local Xcode package graph failed to expose local Core/CacheClient products despite successful independent CI. Diagnose narrowly; do not erase caches or claim that failure is fixed without execution evidence.
- Watcher reconnect after control-stream interruption remains a separate focused change. Physical Apple TV, audible audio and live Bilibili/proxy validation are not part of this fixture suite.
- Runner image inventories are only preflight context: [official macOS 26 inventory](https://github.com/actions/runner-images/blob/main/images/macos/macos-26-Readme.md). Record the actual toolchain, simulator and test outcome from each execution.

## Implementation And Evidence
- Dedicated `MacOSNetPlayerUIE2E` / `TVOSNetPlayerUIE2E` schemes select UI-testing bundles only; existing unit-test schemes are unchanged. TestAction explicitly maps the loopback endpoint build setting without inheriting LaunchAction arguments/environment. Each run overrides the app bundle identifier and uses debug-only isolated model preferences.
- Normal playback controls expose a visible, accessible timeline/state and pause/resume alongside the existing skip/speed controls. macOS UI coverage selects item 55, measures actual 2x progression against a monotonic clock and replays the generated 92-second clip without seeks to natural completion; tvOS coverage uses remote focus/selection and verifies real media progression. These are implemented assertions, not yet an executed-test pass.
- Both UI bundles built successfully locally. Async XCTest lifecycle hooks replaced unsafe synchronous actor access and the deprecated failure hook; the final build emitted no UI-test actor/deprecation warnings. Build evidence: `.codex-tmp/ui-e2e-20261022/app-build/`.
- The first local macOS execution stopped before the test runner established its connection (exit 65 after 383 seconds), so it supplies no executed assertion or playback pass. A separate Computer Use attempt reported a locked Mac and failed automatic unlock; that observation does not prove the runner failure's cause. Independent CI execution remains required.
- After the user reported unlocking the Mac, a second bounded run also exited 65 before connection (349 seconds; runner reported SIGKILL). Read-only verification then found an invalid resource signature on the runner generated with signing disabled. macOS test builds now use local ad-hoc signing with an empty team; tvOS simulator builds retain disabled signing. A subsequent macOS build-for-testing passed, and both app and runner passed `codesign --verify --deep --strict`, reporting `Signature=adhoc` / no team. No UI execution after this correction has yet established that the bootstrap failure is resolved.
- Helper regressions: 31 passed after GitHub review fixes, including exited-leader descendant cleanup, actual Xcode UI-bundle schema, failed-exit diagnostics/error precedence, deadline/output limits, platform-specific inventory/signing, archive-before-delete, endpoint/bundle isolation and rejecting zero/skipped UI results. Workflow/shell lint passed. A real isolated Rust startup smoke generated 55 media items, verified both loopback listeners and reaped its process; no Xcode or UI execution was counted by that smoke.
- macOS execution records its Apple toolchain without querying unused CoreSimulator state. tvOS retains required runtime/device preflight; the workflow bounds its metadata steps to two minutes each. A local tvOS attempt stopped during simulator inventory before creating a device or starting the server, Xcode or UI assertions. Timeout diagnostics now preserve the command/deadline and report unverified cleanup separately rather than replacing the original failure with a signal-permission error.
- Initial non-UI regression: Rust 1,239 passed / 1 pre-existing opt-in ignored, release build passed; SwiftPM 370 passed; probe 30 self-tests passed without a playback URL. Shared source fingerprints were unchanged across those runs. Receipts: `.codex-tmp/ui-e2e-20261022/regression/`.
- Retained runner diagnostics are allowlisted and capped at 32 MiB total / 20 MiB per xcresult. Owned fixtures/state are deleted after staging, and only the newly created tvOS simulator is removed. Existing simulator data, production services and saved credential profiles are not cleanup targets.
