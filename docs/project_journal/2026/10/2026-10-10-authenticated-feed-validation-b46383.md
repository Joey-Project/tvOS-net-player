## Approved V2 Compatibility and Automatic Pagination
- The previous no-protocol-change premise was incomplete: V2 currently rejects every truncated resolution, while only the legacy reply exposes truncation. Add `candidates_truncated` as field 9 of `BilibiliResolutionSession`, preserving existing field numbers and the default-false wire behavior.
- Admit a nonempty bounded candidate window into the existing immutable session store and carry the truncation marker unchanged on every page. Preserve all hard count, byte, string, identity, context, and selection limits. A truncated window with no selectable candidates is budget exhaustion, not a successful empty account.
- Shared AppCore and both clients automatically request the next existing snapshot page as the user reaches the list's end. Retain explicit retry, single-flight loading, stale-session protection, and cancellation. Surface the limited-window state, including when all available snapshot pages have loaded.
- This automatic pagination traverses only the server's frozen candidate window. It neither exposes the core cursor nor extends a session by fetching additional upstream pages. A new resolution is required for a new window.
- Give the start-resolution RPC and shared view model a dedicated 120-second default deadline, leaving ordinary RPCs, server capability checks, and snapshot-page loads on their existing shorter timeout. A client-side 10-second deadline must not preempt the server's admitted 90-second metadata operation. Keep the resolution deadline injectable for deterministic tests and preserve cancellation.
- Add protocol/default compatibility, partial-window pagination and selection, automatic-loading, error/retry, and stale-response tests. Rerun full Rust and Apple gates after these changes rather than carrying forward receipts for the older schema and client.
