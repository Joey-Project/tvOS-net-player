# Read-only HLS Playback Readiness

## Scope
- Build on [PR #92](https://github.com/Joey-Project/tvOS-net-player/pull/92) and the [active recovery-latency workstream](2026-11-10-native-abr-latency-b46399.md).
- Add a backward-compatible read-only gRPC query for one registered HLS session, exact variant and explicit media-time window. Return cache evidence and recent origin delivery evidence separately, not a recommendation to switch.
- Do not change AVPlayer, shared AppCore, default buffering, whole-asset fill, foreground scheduling, media URLs, persistent cache/CDN formats or the BBDown API. Production assisted switching remains a later design decision.

## Cache Evidence
- Report readable, missing or unknown. Readable requires the initialization data and every indexed video/audio fragment overlapping the requested window to be locally readable under the existing cache identity/integrity contract.
- Use known complete-resource indexes or bounded cached MP4 SIDX data only. Never extrapolate time from a proportional file offset or fetch an index, trailer, source metadata or media from the origin during this query.
- Bound windows to 60 seconds, selected ranges to 128, charged read/hash work to 64 MiB per query, buffers to 8 MiB and concurrent inspections to two per store. Contention or exhausted budgets are unknown, not false misses or successful readiness.
- Distinguish a proven gap from missing/unreadable indexes, identity changes, corrupt selected partial extents, I/O errors and out-of-range windows. Unknown takes precedence when combining video and audio evidence.
- Protect object identity and selected checkpoint hashes. Benign metadata changes or unrelated directory-entry churn are not evidence of content mutation. Completed-cache readability is not a new whole-file cryptographic or decoder guarantee.
- Keep lifecycle and I/O guards alive until bounded blocking inspection really ends, even when the RPC is cancelled. Do not promote a query into foreground fill or start download work.

## Origin Evidence
- Retain bounded process-local measurements for the exact representation and current candidate origins. Use monotonic age with a 30-second freshness limit; persisted ranking EWMAs and another video's host history are not current supply evidence.
- Only a completed nonempty transfer with a valid elapsed duration can produce throughput evidence. Unmeasured success must not extend the age of an old sample or revive a failed one. Failure invalidates evidence; cancellation and partial delivery do not manufacture health.
- Capture the monotonic event time at the observation site, before deferred recording. Queueing delay counts toward age; executing an old recording job must not make its sample fresh again. Older arrivals cannot overwrite newer measured supply or invalidate its ordering.
- Keep failure decisions as bounded process-local tombstones, including when no prior measurement exists. Evicting an ordering barrier must not let an older queued success revive it; conservatively unknown evidence is acceptable under memory pressure. Neither tombstones nor eviction-order state belong in the persisted ranking schema.
- Report delivered goodput and optional first-byte latency, not an asserted link capacity or guarantee of future bandwidth. Application pacing and consumer backpressure can affect these observations.
- A restart begins with unknown recent evidence. Do not persist the new observations or return upstream URLs, headers, credentials or raw errors.

## Control-plane Contract
- Add `CacheService.GetHlsPlaybackReadiness` and a capability declaration without changing existing methods. Validate identifiers and finite window bounds before inspection.
- Bind the response to the exact session/variant and recheck registry generation and identity afterward. A changed session yields unknown and no origin evidence.
- Return typed reasons, charged inspection bytes, relative sample ages and freshness limits. No media bytes, playback URL, absolute monotonic timestamp, cache lease or overall safe-to-upshift boolean belongs in the response.
- Generation identifies a process-local observation; it is not durable cross-restart authority. Future cross-device decisions must account for receipt delay and revalidation rather than comparing device uptimes.
- The query does not restore or refresh upstream credentials and does not assert that a variant is currently advertised. Future switching still needs the normal serving/compatibility checks and a usable media path.

## Validation
- Development checks pass for 15 cache-inspection tests, three window/index tests, 33 CDN-history tests, two media-observation tests and the loopback generated-client RPC contract test. These 54 focused checks do not replace frozen-head delivery evidence.
- Exercise cache-only readable/missing/unknown cases, audio/init coverage, bounded index planning, limits, contention, selected-content/identity changes, benign metadata churn and cancellation.
- Cover fresh/stale/missing/restarted origin evidence, representation isolation, unmeasured success, partial/cancelled delivery, failure invalidation and bounded memory.
- Validate the actual generated gRPC route over loopback and prove no origin requests or cache/fill writes are created by inspection.
- Run complete local tests/lint/format, the unchanged fixed-signed native suite with verified system mute, current-head GitHub CI/UI/native evidence and GitHub Codex review. Resolve every conversation before ordinary exact-head merge.

## Next Steps
1. Use the read-only observations to agree on cache-hit versus origin-dependent recovery criteria and a production handover mechanism. Keep the pure automatic long recovery gate even if assisted recovery is later added.
2. Add shared AppCore consumption only with an agreed switching policy, receipt-age handling and normal serving/compatibility checks. This foundation does not itself initiate a switch or prefetch.
3. Continue the remaining native cache lifecycle/offline roadmap after recovery optimization.
